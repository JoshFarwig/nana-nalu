# Spot Condition Profiles — Implementation Plan

## Overview

New feature: users create **condition profiles** on surf spots defining "good conditions" thresholds. When current forecast data (from Redis) matches a profile, the spot lights up on the map. AND logic within a profile (all specified fields must match), OR across profiles (any match = green icon + badge count).

## Step 2 — Model

**File:** `models/spot_condition_profile_model.py`

```
SpotConditionProfile(Base, TimestampMixin)
├── id: int (PK)
├── spot_id: int (FK → surf_spots.id, ondelete=CASCADE)
├── user_id: int (FK → users.id, ondelete=CASCADE)
├── name: str (String(100)) — e.g. "Winter NW Swell", "Summer South"
│
├── Wave (maps to ForecastPoint.wave)
│   ├── wave_height_min/max: float | None    → wave.height (meters)
│   ├── swell_height_min/max: float | None   → wave.swell_height (meters)
│   ├── wave_period_min/max: float | None    → wave.peak_period (seconds)
│   └── wave_direction_min/max: float | None → wave.peak_direction (degrees 0-360)
│
├── Wind (maps to ForecastPoint.wind)
│   ├── wind_speed_min/max: float | None     → wind.speed (m/s)
│   └── wind_direction_min/max: float | None → wind.direction (degrees 0-360)
│
├── Tide (maps to ForecastPoint.tide)
│   └── tide_height_min/max: float | None    → tide.height (meters)
│
├── is_active: bool (default True)
│
└── Relationships
    ├── spot → SurfSpot (back_populates="condition_profiles")
    └── user → User (back_populates="condition_profiles")
```

**Key design notes:**

- All condition fields nullable — `None` pair = "don't care" (always passes)
- Direction fields support wrapping: `min > max` means wrapping around north (e.g., 330°→030°)
- Units match forecast schema exactly (meters, m/s, seconds, degrees)
- `is_active` lets users toggle profiles without deleting

**Relationships to add in existing models:**

- `user_model.py` line 46 area: `condition_profiles: Mapped[list["SpotConditionProfile"]] = relationship(back_populates="user")`
- `surf_spot_model.py` line 36 area: `condition_profiles: Mapped[list["SpotConditionProfile"]] = relationship(back_populates="spot", cascade="all, delete-orphan")`
- Both need TYPE_CHECKING import for `SpotConditionProfile`

## Step 4 — Schemas

**File:** `schemas/spot_condition_profile_schema.py`

**Request schemas:**

- `SpotConditionProfileBase` — shared fields with validation:
  - `@model_validator(mode="after")` to ensure range pairs are both-set-or-both-None
  - Non-direction pairs: `min <= max` enforced
  - Direction pairs: `min > max` allowed (wrapping)
  - `@field_validator` to round floats to 2 decimal places
- `SpotConditionProfileCreate(SpotConditionProfileBase)` — adds `spot_id: int`
- `SpotConditionProfileUpdate(BaseModel)` — all fields optional (partial update)

**Response schemas:**

- `SpotConditionProfileResponse(SpotConditionProfileBase)` — adds `id`, `spot_id`, `user_id`, timestamps, `from_attributes=True`
- `ProfileMatchResult` — `profile_id`, `profile_name`, `user_id`, `matched: bool`
- `SpotConditionStatus` — per-spot: `spot_id`, `is_firing: bool`, `matched_count: int`, `total_profiles: int`, `profiles: list[ProfileMatchResult]`
- `BatchConditionStatusResponse` — `spots: list[SpotConditionStatus]`, `evaluated_at: datetime`

## Step 6 — Service (core logic)

**File:** `services/spot_condition_service.py`

Class: `SpotConditionService`

**Constructor dependencies:**

- `profile_repo: AsyncSpotConditionProfileRepository`
- `spot_repo: AsyncSurfSpotRepository`
- `crew_repo: AsyncCrewRepository`
- `forecast_service: ForecastService`
- `session: AsyncSession`

### CRUD Methods

- `create_profile(user_id, data)` — validates spot access (own spot or crew member), creates, commits
- `update_profile(user_id, profile_id, data)` — validates ownership (only creator), updates, commits
- `delete_profile(user_id, profile_id)` — validates ownership, deletes, commits
- `get_profiles_for_spot(spot_id)` — returns all profiles (from all users)
- `get_user_profiles(user_id)` — returns user's profiles across all spots

### Authorization Helpers

- `_validate_spot_access(user_id, spot_id)` — user owns spot OR is member of spot's crew
- `_validate_profile_ownership(user_id, profile_id, action)` — only creator can update/delete

### Matching Engine

**`evaluate_batch_conditions(user_id)`** — the main map endpoint:

1. Get all user-viewable spots via `spot_repo.get_all_user_viewable_spots(user_id)` (existing method)
2. Batch-load all profiles via `profile_repo.get_all_for_spot_ids(spot_ids)` (single query)
3. Group profiles by spot_id
4. For each spot: get current conditions, evaluate each profile, build `SpotConditionStatus`

**`_get_current_conditions(spot_id)`** — multi-provider aggregation:

1. Call `forecast_service.get_forecasts(spot_id)` to get all `ProviderForecast` objects from Redis
2. For each provider's forecast, find the `ForecastPoint` nearest to `now()` (using `min()` on `abs(valid_time - now)`)
3. Extract wave/wind/tide data from the nearest point, keeping the provider with the point closest to now per category
4. Return flat dict: `{"wave_height": float, "wave_peak_direction": float, "tide_height": float, ...}`

**`_evaluate_profile(profile, current_conditions)`** — AND logic:

- For each field pair (min/max): if both None → skip (pass). If specified but current data missing → fail. If specified and data exists → check range.
- Direction fields use wrapping logic: `if min <= max: normal range check. if min > max: value >= min OR value <= max`

**`_direction_in_range(value, min_deg, max_deg)`** — compass wrapping:

- Normal: `min <= max` → `min <= value <= max`
- Wrapping: `min > max` (crosses north) → `value >= min OR value <= max`
